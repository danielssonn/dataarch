Data Platform: 90-Day Implementation Plan

Objective

Within 90 days:

  • Lay the technical and governance foundation for the data platform.
  • Implement the core data ontology as the primary design driver.
  • Deliver end-to-end, ontology-aligned pipelines from ledger and payments.
  • Prototype a Flink-based statement engine on synthetic/early data.
  • Ensure PCI-aligned security, observability, and IaC from day one.

This is the rigorously engineered foundation; Q2 2027 and beyond will harden and extend it.

Assumptions

  • Cloud: Azure (confirmed).
  • Tools: Databricks, Confluent Kafka, AKS, Unity Catalog, Neo4j.
  • Primary data sources for MVP: Ledger and Payments systems.
  • Team: 10 data engineers + architectural leadership.
  • No Camunda dependency in this phase; future consumer/provider of data.

Week 1–2: Architect, Define Ontology, Align

Goals

  • Finalize architecture and tech stack.
  • Define core data taxonomy and ontology.
  • Define statement use case boundaries and rules.
  • Align with leadership and dependent teams.

Key Work

  • Architecture:
    • Confirm stack: Azure, Databricks, Confluent Kafka, AKS, Neo4j, Unity Catalog.
    • Reference diagrams: logical, physical, data flow.
    • Document PCI DSS 4.x alignment approach.
  • Ontology v1:
    • Canonical entities:
      • Customer, Corporate
      • Account, Product, Contract
      • Transaction, Balance, Statement
      • High-level LC, Lending Facility, Exposure
    • Define:
      • Identifiers, relationships, ownership, update semantics
  • Statement Use Case:
    • Define:
      • Required elements (balances, movements, references)
      • Frequency, currencies, corrections, hierarchy
    • Specify dependencies on ledger and payments.

Deliverables

  • Architecture overview + diagrams.
  • Ontology/taxonomy v1 (implementation-ready).
  • Statement generation design (sources, rules, outputs).
  • 90-day plan (this document).

Week 3–4: Deploy Platform Foundation (IaC + Lakehouse)

Goals

  • Deploy core Azure infrastructure via IaC.
  • Implement ontology-aligned lakehouse and governance.

Key Work

  • Infrastructure (Terraform/Bicep):
    • Networking: VNets, subnets, private endpoints.
    • Security: Key Vault, Entra ID, RBAC.
    • Logging & monitoring: centralized logs/metrics.
    • Databricks workspace (dev/test).
    • Confluent Kafka cluster.
    • AKS cluster (base).
  • CI/CD:
    • GitHub repos and branching model.
    • Pipelines for infra and data pipeline deployments.
  • Lakehouse & Governance:
    • ADLS Gen2 + Delta Lake layout (bronze/silver/gold).
    • Unity Catalog:
      • Catalogs/schemas mapped to business domains.
      • Access policies aligned to ontology.
  • Ontology in the platform:
    • Canonical schemas (silver/gold) for:
      • Customer, Corporate, Account, Product, Contract
      • Transaction, Balance, Statement
    • Enforce naming conventions and domain boundaries.

Deliverables

  • Secure platform scaffold in dev/test.
  • Ontology-backed canonical schemas live in Databricks.
  • CI/CD pipelines operational.

Week 5–6: Ingest Ledger & Payments; Establish Streaming

Goals

  • Connect ledger and payments into canonical models.
  • Establish streaming foundation using Kafka + Flink/Databricks.

Key Work

  • Batch ingestion:
    • Ledger → Bronze → Canonical.
    • Payments → Bronze → Canonical.
    • Mapping rules from ontology.
  • Event streaming:
    • Kafka topics: ledger_events, payment_events, statement_events.
    • Databricks Structured Streaming / Flink:
      • Consume events → normalize via ontology → write Delta tables.
      • Running balances, daily/rolling snapshots.
  • PCI/Security:
    • Encrypt PII/financial fields.
    • RBAC and restricted access for sensitive data/topics.

Deliverables

  • End-to-end flows: ledger/payments → Kafka → canonical tables.
  • Near-real-time canonical events and aggregates available.

Week 7–8: Statement Engine Prototype

Goals

  • Implement prototype statement generation.
  • Expose basic APIs for consumption.

Key Work

  • Statement engine (Flink/Databricks):
    • Compute lines from canonical transactions and balances.
    • Apply grouping, currency, hierarchy, and formatting rules.
    • Ensure idempotency, versioning, audit trail.
  • Persistence:
    • Statements as Delta tables.
    • Artifacts (PDF/XML) in ADLS.
  • APIs (AKS):
    • GetStatements, GetBalances.
    • Consume canonical data, PCI-aligned access.
  • Testing:
    • Validate on synthetic/early data.
    • Verify accuracy vs ledger/payments and latency.

Deliverables

  • Working statement flow: events → canonical data → statements → API.
  • Demoable prototype for leadership.

Week 9–10: Prepare for Q4 Scope; Harden and Document

Goals

  • Extend ontology for supply chain, LC, lending.
  • Harden platform for multi-year use.
  • Produce final documentation and roadmap.

Key Work

  • Ontology v2 (draft):
    • Supply chain vendor entities.
    • LC and lending constructs.
    • Containment patterns for vendor data.
  • Platform hardening:
    • Observability: logs, metrics, traces, alerts.
    • Data quality: completeness, conformance checks.
    • Runbooks: basic operational procedures.
  • Documentation:
    • Platform architecture.
    • Ontology/taxonomy reference.
    • 90-day outcomes + multi-year roadmap with maturity model.

Deliverables

  • Extended ontology draft for Q4 scope.
  • Observability and data quality baselines.
  • Final architecture and roadmap documentation for leadership.
