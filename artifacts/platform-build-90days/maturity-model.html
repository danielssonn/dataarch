Data Platform: Capabilities Maturity Model

Purpose

This model defines platform capabilities, their maturity levels, and the progressive path from 90-day foundation through Q4 2027 and into 2028–2030. It is used to:

  • Guide investment in clear maturity steps.
  • Communicate a multi-year vision to leadership.
  • Ensure each phase builds on a stronger, not just bigger, platform.

Maturity Levels

  • 0: Ad Hoc / Fragmented
  • 1: Standardized Foundation
  • 2: Integrated & Real-Time
  • 3: Intelligent & Governed
  • 4: Autonomous & Business-Led

Capability 1: Ontology & Data Modeling

  • 0: Siloed models, inconsistent terminology.
  • 1: Core taxonomy defined; canonical entities implemented; all new work aligned.
  • 2: Extended ontology across products (statements, LC, lending, supply chain).
  • 3: Ontology enforced via automated checks; lineage from source → ontology.
  • 4: Business-led ontology evolution with self-service, tool-supported modeling.

Target:

  • 90 days: Level 1
  • Q4 27: Level 2 for in-scope domains
  • 2028–2030: Level 3–4

Capability 2: Ingestion & Integration

  • 0: Manual extracts, bespoke scripts.
  • 1: Centralized ingestion patterns; Kafka + batch pipelines; governed schemas.
  • 2: Near-real-time from core systems; standardized connectors; event schemas.
  • 3: Data contracts with producers/consumers; quality SLAs; monitoring.
  • 4: Plug-and-play onboarding of new systems via templates.

Target:

  • 90 days: Level 1 (ledger/payments)
  • Q2 27: Level 2 for statement-critical flows
  • Q4 27+: Level 3 patterns

Capability 3: Streaming & Real-Time

  • 0: No streaming; only batch.
  • 1: Streaming bus in place (Confluent Kafka); basic real-time aggregations.
  • 2: Streaming powers operational use cases (statements, alerts).
  • 3: Complex event processing and risk on streaming data.
  • 4: Real-time embedded into product operations and AI decisioning.

Target:

  • 90 days: Level 1
  • Q2 27: Level 2 for statements
  • Q4 27–2028: Level 3 for risk, LC, lending

Capability 4: Analytics & Lakehouse

  • 0: Disparate warehouses; no unified model.
  • 1: Databricks lakehouse with Delta Lake; governed canonical schemas.
  • 2: Trusted analytics layer; self-service zones for analysts.
  • 3: Advanced analytics (ML/AI) on canonical data.
  • 4: Fully self-service with guardrails; automated insights.

Target:

  • 90 days: Level 1
  • Q2–Q4 27: Level 2
  • 2028+: Level 3, selected Level 4

Capability 5: Governance, Security & PCI

  • 0: Minimal controls; scattered policies.
  • 1: Central catalog (Unity Catalog); RBAC; PCI DSS baseline controls.
  • 2: Strong lineage; domain-based RLS; automated PCI checks.
  • 3: Continuous compliance monitoring; data contracts; audit automation.
  • 4: Policy-as-code fully embedded in CI/CD; zero-trust operations.

Target:

  • 90 days: Level 1 (PCI-aware)
  • Q2 27: Level 2 for statement/financial flows
  • Q4 27+: Level 3

Capability 6: APIs & Platform Services

  • 0: Direct DB access; point-to-point integrations.
  • 1: Central API layer on AKS; defined contracts.
  • 2: APIs as primary access to canonical data.
  • 3: Developer portal; versioned APIs; usage analytics.
  • 4: Marketplace-style self-service data products.

Target:

  • 90 days: Level 1 (statements APIs)
  • Q2 27: Level 2
  • Q4 27+: Level 3

Capability 7: Automation, IaC & Developer Experience

  • 0: Manual provisioning; inconsistent environments.
  • 1: IaC for core infra; standardized repos and pipelines.
  • 2: Environment-as-code; reusable templates; GitOps.
  • 3: Self-service provisioning for data teams.
  • 4: AI-assisted dev and ops; zero-touch deployments.

Target:

  • 90 days: Level 1
  • Q4 27: Level 2
  • 2028+: Level 3–4

How to Use

  • Use this model to:
    • Communicate the multi-year vision to leadership.
    • Justify incremental investment.
    • Ensure each phase is a clear maturity step, not just “more features.”
  • 90-day success is:
    • Solid Level 1 across key capabilities.
    • Ontology implemented and enforced.
    • Platform ready for Q2/Q4 27 buildouts.
